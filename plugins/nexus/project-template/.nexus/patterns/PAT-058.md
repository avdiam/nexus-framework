# PAT-058: Documentation-Driven Discovery
*Version: 4.0.1 | Date: 2026-08-20 | Sprint: 109*

## Metadata
- **Type**: methodology
- **Composite**: false
- **Status**: active
- **Created**: 2025-10-20

## Problem
System capabilities remain hidden or undocumented. Teams work with incomplete understanding, missing opportunities to leverage existing functionality.

## Context
- **Use When**: Complex systems with incomplete docs, gap suspected between perceived and actual state, understanding needed before major changes, before major architecture decisions (document first to discover what exists)
- **Not When**: System genuinely simple, documentation accurate, time constraints prevent thorough analysis
- **Prerequisites**: Time allocation (2-3x initial estimate)

## Solution
Systematic documentation creation reveals hidden capabilities.

### Process
```yaml
step_1_goals:
  - "Define documentation artifacts to create"
  - "Set clear scope and objectives"

step_2_deep_analysis:
  - "Read EVERY system file methodically"
  - "Document actual state, not assumptions"
  - "Track 'thought X, actually Y' discoveries"

step_3_progressive_understanding:
  order: "Core files → command modules → data structures → supporting systems"

step_4_synthesis:
  - "Consolidate findings into coherent documentation"
  - "Identify emergence patterns (capabilities > components)"
  - "Update system files with discovered intelligence"
```

## Rationale
- **Theoretical Basis**: Systematic analysis uncovers what ad-hoc exploration misses
- **Empirical Evidence**: Sprint 025 discovered system 2x more sophisticated than understood
- **Key Insight**: 60-90% of needed features often already exist but are undocumented

## Anti-Patterns
- **Documenting assumptions**: Writing based on beliefs, not verified state
- **Rushing analysis**: Missing discoveries due to time pressure
- **Focusing on known**: Only documenting familiar components

## Relationships
- **Synergies**: None
- **Conflicts**: None

## Consequences
- **Benefits**: Comprehensive understanding, hidden features revealed, reduced confusion
- **Tradeoffs**: Requires significant time investment
- **Risks**: Scope creep if not bounded

## Examples
### Success: Sprint 025
- Goal: 5 documentation artifacts
- Process: Analyzed 47+ system files
- Discovery: System 2x more sophisticated than understood
- Result: 8 artifacts + system enhancements
