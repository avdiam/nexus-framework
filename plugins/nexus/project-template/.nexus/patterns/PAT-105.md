# PAT-105: Phase Collapse on Pre-Drafted Canonical Sources
*Version: 1.0.0 | Date: 2026-05-12 | Sprint: 077*

## Metadata
- **Type**: methodology
- **Status**: active
- **Created**: 2026-05-12

## Problem
When canonical sources upstream of an issue (research synthesis, prior-pass deliverables, third-pass-consolidated proposals) pre-resolve not just patch text but also design decisions (carve-out semantics, schema fields, version-bump magnitudes, sub-step placements), default phase effort estimates over-budget. Analysis defaults to "resolve all design questions"; Build defaults to "draft all content"; Validate defaults to "broad-spectrum review." Each phase carries unnecessary effort when the upstream canonical work has already resolved most of its design surface. Equally dangerous is the opposite drift — treating the pre-drafted state as a license to skip the adversarial surface, since meaningful design decisions still surface inside phases even under maximal upstream resolution.

## Context
- **Use When**:
  - An issue arrives with canonical sources (synthesis docs, revised proposals, third-pass artifacts) whose verdicts have already been ratified upstream
  - Solution-Design fields already enumerate carve-outs, schema additions, version targets, and sub-step placements before Analysis begins
  - Build's design space is mostly transcription + delta-compose work, not original authoring
  - Multi-phase issues where upstream phases of a prior issue resolved the design questions for this one
- **Not When**:
  - Canonical source is a draft proposal, not a ratified verdict — design surface is real
  - The issue extends or contradicts the canonical scope (scope-creep territory)
  - Cross-cutting concerns (cross-skill drift, system-wide protocol additions) are part of the issue surface — those need full Analysis even under canonical patches
- **Prerequisites**: Canonical sources must be loaded into the issue's reference chain at creation; Solution-Design should explicitly cite them.

## Solution
Calibrate phase effort to canonical resolution density. The collapse compresses *authoring*; it does NOT compress *verification* or *adversarial surface*.

### Implementation

1. **Analysis under collapse** — Cross-check canonical claims against current file state on disk. Surface novel decisions canonical sources don't resolve (typical: 2–4 design micro-decisions per C:3 issue — version-bump magnitude, key format, exact phrasing of cross-pack parallel-form text). Compose Solution-Design as transcription + delta. **Run blind-spot pass anyway** — collapse does not eliminate blind-spot risk on the residual design surface.

2. **Build under collapse** — Patch application + version-bump verification + brief authoring of any text canonical sources didn't fully specify (typical: 1–3 inline drafts per C:3 issue — cross-pack note phrasing, partial-population handling, lookup-key clarifications). **Run adversarial review at full discipline** — ~2 MED findings per C:3 issue land outside canonical scope (empirically observed across 3 reproductions). Skipping adversarial review under collapse is the dominant failure mode.

3. **Validate under collapse** — Tier 3 cold disk re-read is load-bearing precisely because Build collapses. Build's in-memory grep results are not a substitute for independent verification of anchors at expected line ranges. Adversarial review at Validate continues to surface ~1 new LOW finding per C:3 issue (typical: edge cases canonical proposals omitted).

### Quick Reference
| Phase | Compresses | Persists |
|---|---|---|
| Analysis | "Resolve design space" → cross-check + delta-compose | Blind-spot pass on residual surface |
| Build | "Draft all content" → patch + brief authoring | Adversarial review (~2 MED/C:3 issue) |
| Validate | "Re-derive verdicts" → confirm canonical claims | Tier 3 cold re-read + adversarial pass |

## Rationale
- **Theoretical Basis**: Pre-drafted canonical sources amortize design cost across the originating sprint and consuming sprints. The consuming issue inherits the resolved design surface; spending equal effort to re-resolve is duplicative. But canonical sources are *finite* — they pre-resolve their stated scope, not the surface adjacent to it. Adversarial review continues to find legitimate work outside canonical bounds because canonical scope is bounded by the originating analyst's frame, not by the consuming implementer's discovery surface.
- **Empirical Evidence**: 3 clean reproductions in Sprint 077 (ISS-162 + ISS-163 + ISS-161): each consumed ISS-159 third-pass-synthesis canonical sources. Each Analysis+Build cycle completed in 2 conversations vs. naive 3–4. Adversarial Review at each Build surfaced ~2 MED findings outside canonical proposal scope — partial-population handling (ISS-161), matrix lookup-key (ISS-161), cross-pack parallel-form phrasing (ISS-163), marker placement (ISS-162). Validate Tier 3 caught zero anchor-drift across the 3 reproductions, but the cold-grep discipline is what produced "zero drift" — not its absence.
- **Design Decisions**: Effort compression is calibrated per-phase rather than uniformly because the failure modes differ. Analysis collapse risks missing residual design questions (mitigated by blind-spot pass). Build collapse risks skipping adversarial review (mitigated by enforcing it as load-bearing). Validate collapse is the highest-risk mode (drift between in-memory Build and disk reality) — mitigated by Tier 3 cold re-read as standing discipline.

## Anti-Patterns
- **Anti-Pattern 1: Skip adversarial review because "everything was pre-drafted"**
  - **Why Wrong**: Empirically, ~2 MED findings per C:3 issue land outside canonical scope across 3 reproductions. Skipping adversarial review under collapse loses those findings; they show up at Validate or in production usage.
  - **Example**: Build accepts canonical patch text without questioning whether interrupted setup-project runs leave partial-population state — partial-population handling is outside canonical scope but real.

- **Anti-Pattern 2: Trust Build's in-memory grep results at Validate**
  - **Why Wrong**: Phase collapse compresses authoring effort, not verification need. Build's claimed anchor positions can drift from disk reality if any inline edit shifts line numbers; only independent cold re-read at Validate catches this.
  - **Example**: Build claims "anchor at L203" in memory; Validate accepts the claim without cold grep; a later inline addition shifted the anchor to L207 silently.

- **Anti-Pattern 3: Treat speculative version bumps as recommendations**
  - **Why Wrong**: Canonical proposal text may speculate "Minor bump for content additions" — but version-bump magnitude is governed by CLAUDE.md File-Operations-Protocol's no-judgment rule (new top-level § = Major). Treating canonical speculation as ratified produces version-bump drift caught only at sprint closure.
  - **Example**: ISS-161 Analysis blind-spot pass caught a Minor/Major drift before Build started — proposal speculated Minor; rule mandates Major for new top-level §.

## Consequences
- **Benefits**: 30–50% phase-effort compression on issues with strong upstream canonical sources (3 conversations vs 5–6 for C:3); preserves quality through adversarial-review-as-mandatory and Tier 3 cold-verification; makes design-surface inheritance explicit and auditable.
- **Tradeoffs**: Requires upstream investment in canonical synthesis (third-pass consolidated artifacts, ratified proposals) that pre-resolves design space — pattern is symbiotic with sprint workflows that produce canonical artifacts, not standalone work.
- **Risks**: Mistaking a draft proposal for a canonical source; skipping adversarial review under the "everything was pre-drafted" misconception (the dominant failure mode); accepting canonical-speculative claims (version bumps, schema field names) as ratified.

## Examples

### Before/After Comparison
**Without Pattern**: Each consuming issue runs full Analysis (resolve design questions from scratch, ~80% redundant with canonical work) → full Build (draft all content from scratch, ~70% redundant) → full Validate. C:3 issue takes 5–6 conversations. Adversarial review either runs at full intensity (correct) or gets skipped under time pressure (the failure mode).

**With Pattern**: Analysis cross-checks canonical claims, surfaces residual design surface (typically 2–4 micro-decisions), composes Solution-Design as transcription + delta — fits in 1 conv. Build executes canonical patches, drafts the 1–3 brief texts canonical sources didn't specify, runs adversarial review at full discipline — fits in 1 conv. Validate Tier 3 cold-grep verifies anchors on disk — fits in 1 conv. Total: 3 conversations for C:3 with all quality gates preserved.

### Application Example
ISS-162 + ISS-163 + ISS-161 in Sprint 077 — all three consumed ISS-159 third-pass-synthesis canonical sources. ISS-162 completed Analysis+Build in 1 conv, Validate+closure in 1 conv. ISS-163 same shape. ISS-161 (C:3, 7-file structural scope) completed Analysis Conv 6, Build Conv 7, Validate+closure Conv 8 — 3 conversations end-to-end. Adversarial Review at Build surfaced 2 MED findings per issue outside canonical scope (partial-population, lookup-key, cross-pack phrasing) — all fixed inline. Validate Tier 3 cold-grep caught zero anchor drift across 3 reproductions.

## Validation
- **Success Indicator**: Issue completes A+B+V cycle in N–1 or N–2 conversations vs naive estimate, with adversarial review still surfacing ~2 MED findings per C:3 issue at Build, and Tier 3 cold-grep at Validate confirming all SC anchors on disk independent of Build's in-memory claims.
- **Edge Cases**: Issues that extend canonical scope (add fields, rename keys, change semantics beyond canonical proposal) — those carry real design surface and the pattern does NOT apply. Test: does Solution-Design require decisions canonical sources don't address? If >4–5 micro-decisions, scope is extending, collapse doesn't apply.

## Notes and Observations
Pattern symbiotic with sprint architectures that produce canonical artifacts (third-pass consolidation, revised proposals, sprint-closure synthesis docs). Diminishing returns above C:4 — high-complexity issues tend to have wider residual design surface even under maximal canonical resolution, so the collapse ratio degrades. Best fit: C:2–C:3 issues with strong upstream canonical scope.
