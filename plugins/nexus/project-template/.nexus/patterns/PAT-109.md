# PAT-109: Disconnect-Not-Delete Guard
*Version: 1.0.0 | Date: 2026-05-22 | Sprint: 084*

## Metadata
- **Type**: principle
- **Status**: active
- **Created**: 2026-05-22

## Problem

Refactors that wire a successor (new hook, new skill, new method) frequently skip the symmetric "delete predecessor + scrub references" steps. The predecessor file remains on disk, its references survive in docs and registries, its permissions stay in settings.local.json. The framework accumulates dead code, stale doc pointers, orphan permissions, and incorrect architecture descriptions — invisible until a comprehensive audit surfaces them. Sprint 072 → Sprint 084 (12 sprints) accumulated 514 dead lines + 3 stale doc pointers + 2 orphan permissions because the predecessor file (`nexus-context-reader.sh`) was disconnected from settings.json wiring when its successor (`nexus-context-stop-hook.sh`) was wired, but never deleted.

## Context

- **Use When**: At every successor-wiring refactor (new hook replaces old hook, new skill replaces old skill, new method replaces old method); when reviewing Build phase commits that introduce a successor; at Validate phase as a quality gate
- **Not When**: When predecessor is intentionally preserved as a fallback / dual-path runtime arrangement (explicitly documented); when successor is purely additive (no predecessor relationship)
- **Prerequisites**: Awareness of the predecessor-successor relationship at refactor time (often surfaced during /nexus-analyze)

## Solution

Pair every "wire successor" step with two explicit symmetric steps in the same commit/PR:

1. **Wire successor** — introduce the new file/method/handler; update consumers.
2. **Delete predecessor** — remove the predecessor file from disk (or remove the method from the surviving file).
3. **Scrub references** — grep all framework surfaces (docs, registries, settings, architecture, init-project hook-copy tables, permissions) for predecessor name + scrub.

### Implementation

At Build phase:
- Emit all 3 steps in the same commit so reviewers see the symmetry.
- Compose commit message with explicit predecessor name + cross-reference scrub count.

At Validate phase (quality gate):
- Grep for predecessor file existence post-successor introduction.
- Grep for predecessor name across `.claude/`, `.nexus/active/`, `init-project` hook-copy tables, settings.local.json permissions.
- Flag any survivors as orphan-on-successor-introduction.

### Quick Reference

| Predecessor type | Scrub surfaces |
|---|---|
| Hook (.sh / .py) | settings.json hooks + settings.local.json permissions + init-project hook-copy table + NEXUS-Architecture.md hooks section + any docs citing the hook |
| Skill (.claude/skills/nexus-X/) | CLAUDE.md Routing-Map + nexus-menu rows + NEXUS-Architecture.md skills section + cross-skill `load /nexus-X` calls + changelog-registry entries |
| Method (within file) | grep within parent file + grep across files calling the method + comments referencing the method by name |

## Rationale

- **Theoretical Basis**: A successor-wiring change has two symmetric halves: introduce + retire. Treating it as half-symmetric (introduce only) creates entropy — the framework remembers states it no longer occupies. Entropy accumulates silently because nothing fails (predecessor disconnected from runtime), but framework surfaces (docs, registries) misrepresent state until a forensic audit surfaces them.
- **Empirical Evidence**: Sprint 072 ISS-155 wired `nexus-context-stop-hook.sh` as the active UserPromptSubmit hook, disconnecting `nexus-context-reader.sh` from settings.json. 12 sprints (Sprint 072 → Sprint 084) elapsed before audit surfaced: 514 dead lines + 3 stale doc pointers (init-project L211 + 2 NEXUS-Architecture rows with inverted descriptions) + 2 orphan permissions. Cost = 1 audit batch (Conv 8 Batch 6) to surface; cost would have been 1 commit at Sprint 072 to prevent.
- **Design Decisions**: Build-phase emission in same commit (vs separate cleanup PR) prevents the cleanup PR from being deprioritized and forgotten. Validate-phase quality gate is the safety net for refactors that skipped Build-phase discipline.

## Anti-Patterns

- **Anti-Pattern 1**: "Disconnect now, delete later" framing
  - **Why Wrong**: "Later" is rarely scheduled; the predecessor persists indefinitely. Sprint 072 → Sprint 084 (12 sprints, 5 weeks) is empirical evidence of this failure mode.
  - **Example**: Sprint 072 ISS-155 commit disconnected reader hook but explicit "scrub references" step absent; cleanup never happened until Sprint 084 audit.

- **Anti-Pattern 2**: Scrubbing only the "obvious" surfaces (one doc file) and missing registries / permissions / architecture
  - **Why Wrong**: Framework surfaces are heterogeneous — predecessor name appears in docs, hook-copy tables, architecture descriptions, registry closure entries, settings permissions. Comprehensive grep across all surfaces is the only way to scrub completely. Partial scrub produces "mostly fixed" state that decays into "still broken" state.

- **Anti-Pattern 3**: "Predecessor file is harmless if disconnected" rationalization
  - **Why Wrong**: Even disconnected, predecessor file shows up in inventory audits, contaminates grep searches, misleads new-instance Claude into thinking the file is active. Cost-of-presence is non-zero.

## Relationships

- **Requires**: PAT-098 (grep-before-rename) — same comprehensive-grep discipline applied to delete + scrub
- **Enhances**: None
- **Conflicts**: None
- **Alternatives**: Manual cleanup PR series (less reliable — gets deprioritized)

## Consequences

- **Benefits**: Prevents accumulation of dead code + stale doc pointers + orphan permissions; framework surfaces stay synchronized with runtime state; future audits find less drift.
- **Tradeoffs**: Build-phase commits become slightly larger (includes scrub diff); requires comprehensive grep at every refactor.
- **Risks**: Over-scrubbing — accidentally deleting references that should be preserved as historical narrative (registries, work-history). Mitigated by scoping the scrub to active framework surfaces, not historical/sprint-archived files.

## Examples

### Before/After Comparison

**Without Pattern (Sprint 072 ISS-155)**:
- Successor wired: `nexus-context-stop-hook.sh` (133L)
- Predecessor: `nexus-context-reader.sh` (514L) — disconnected from settings.json hooks but not deleted
- Scrub: NOT performed — 3 doc pointers + 2 permissions persisted
- Result: 12-sprint accumulation; 514 dead lines + cross-doc drift; required Sprint 084 audit to surface

**With Pattern**:
- Successor wired in commit X
- Same commit deletes predecessor file + scrubs settings permissions + scrubs init-project hook-copy table + scrubs NEXUS-Architecture hooks rows
- Result: framework surfaces synchronized on day 1; no accumulation

### Application Example

ISS-184 Sprint 084 audit surfaced the Sprint 072 → Sprint 084 drift; spawned ISS-β (Sprint X.2) with explicit pairing-discipline requirement for context-reader.sh DELETE in same commit as scrub-references step (audit-deliverable §6.2). PAT-109 codifies the discipline for future refactors so audits don't have to find it 12 sprints later.

## Validation

- **Success Indicator**: After a successor-wiring refactor, grep for predecessor name returns zero hits in active framework surfaces (.claude/, .nexus/active/, CLAUDE.md, settings.json, settings.local.json); historical/sprint-archived files may retain references as narrative.
- **Edge Cases**: Predecessor that is also called as fallback (dual-path) — document explicitly; this pattern doesn't apply to intentional duality.
