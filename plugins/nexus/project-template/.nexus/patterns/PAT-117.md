# PAT-117: Analysis-Prelock-Reformulation-When-Strip-Vacuous
*Version: 1.0.0 | Date: 2026-05-27 | Sprint: 089*

## Metadata
- **Type**: practice
- **Status**: active
- **Created**: 2026-05-27

## Problem

Cleanup/strip operations on guidance-bearing sections can leave a section vacuous of *guidance* even when content removal is correctly identified by the strip plan. Pure row-strip and section-removal-when-vacuous-of-content treatments cover two cases; they miss a third: the section still contains content after the strip but no longer fulfills its instructional purpose. When this third case is only discovered at Build (reactive PAT-085 reformulation), Build becomes a discovery phase for architectural calls instead of executing locked decisions, lengthening the Build→§POST-TYPE→Validate walk loop and deferring a decision the Analysis phase had the evidence to make.

## Context

- **Use When**:
  - Cleanup/refactor/simplification issues over multiple guidance-bearing skill or doc sections
  - Topic-1-style treatment decisions at Analysis where the strip set crosses guidance content
  - Cascade-companion follow-on issues to backbone cleanups (multi-skill cascade where prior backbone work established the strip vocabulary)
  - Sprints in a strategic-pivot arc closing the *shape* of a removed concept (not just the vocabulary)
- **Not When**:
  - Pure code refactor without guidance content
  - Vocab-only cleanups confined to non-instructional surface (variable renames, comment normalization)
  - Single-section strips where Build-time reactive PAT-085 is cheap to walk
- **Prerequisites**: Analysis phase Topic-1-style treatment decision step; awareness of PAT-085 clarity-over-compression

## Solution

At Analysis Topic-1-style treatment decisions for cleanup/refactor issues, pre-lock **three** treatment branches (not two):

1. **Row-strip** — remove the multi-env/conditional vocabulary within an otherwise still-functional structure (table rows, parenthetical qualifiers, sole-branch conditionals collapsed inline).
2. **Section-removal when vacuous of content** — remove the entire `###` subsection when its content was purely the vocabulary being stripped (vestigial single-row tables, sole-branch headers with no surviving body).
3. **Reformulation per PAT-085 when vacuous of guidance** — when pure strip would leave a section with surviving content but no longer fulfilling its instructional purpose, replace the section's directive with a single-env equivalent that preserves guidance. This is a proactive Analysis decision, not a Build-time discovery.

### Implementation

1. At Analysis Topic 1, walk each scope file's stripped section via Mental Simulation: "if I strip every multi-env token here, does the section still provide guidance?"
2. If yes → row-strip or section-removal-when-vacuous-of-content (cases 1–2).
3. If no but the section's purpose still applies under single-env → pre-lock Reformulation (case 3): note the reformulation target and the PAT-085 application site in the Implementation-Plan, with a draft of the replacement directive.
4. If no and the section's purpose is dissolved by the strategic shift → section-removal (case 2 broadens).
5. Build executes the pre-locked branch. §POST-TYPE deviation analysis still applies, but reformulation calls are no longer Build-time discoveries.

### Quick Reference

```
ANALYSIS TOPIC 1 — three branches per section in strip set:

  vocab still inside intact guidance? ──► (1) row-strip
  content vacuous after strip?       ──► (2) section-removal
  guidance vacuous after strip?      ──► (3) PAT-085 reformulation
                                         (PRE-LOCK at Analysis,
                                          not reactive at Build)
```

## Rationale

- **Theoretical Basis**: Sections in skill files exist to provide guidance. Removing the vocabulary may collapse the only guidance the section provided. The Analysis phase has the same evidence Build would have at the reformulation site — there is no reason Build needs to be the discovery phase. Pre-locking compresses the decision distance from Build-discovery → §POST-TYPE Walk → Validate re-affirm down to Analysis-lock → Build-execute.
- **Empirical Evidence**: Sprint 089 ISS-193 `.claude/skills/nexus-maintain/SKILL.md` §B "Detect Environment + Mode" → "Mode Selection" rename surfaced at Build Mental Sim pass, not Analysis Topic 1. Pure strip of the multi-env-conditional content (L95 "Boot [TRACKING]: CC/Cowork → Mode B candidate. Chat → Mode A.") would have left §B with no mode-selection guidance. Reformulation per PAT-085 was the correct call — Validate (Conv 3) independently affirmed it. Had Analysis pre-locked branch 3 for §B, Build would have executed the locked decision instead of making it.
- **Design Decisions**: Branch enumeration at Analysis is a one-time cost per cleanup ISS. Mental Sim pass per scope-file section is fast (seconds per section). Discovering reformulation at Build with no Analysis hook trades that fast Analysis pass for a Build-time architectural call + §POST-TYPE deviation entry + Validate re-affirmation — three downstream phases doing work Analysis could have absorbed.

## Anti-Patterns

- **Anti-Pattern 1: Two-Branch Default ("strip or remove")**
  - **Why Wrong**: Forces every guidance-vacuum case to surface at Build. Build becomes a discovery phase for reformulation, not an execution phase.
  - **Example**: ISS-193 Analysis locked only "row-strip" and "section-removal-when-vacuous"; §B rename in nexus-maintain emerged at Build Mental Sim and required Implementation-Log Deviation entry + §POST-TYPE Walk.

- **Anti-Pattern 2: Reactive PAT-085 Only at Build**
  - **Why Wrong**: PAT-085 reformulation is correct medicine but reactive timing means the architectural call is unlocked when it could have been locked. Validate then has to independently confirm.
  - **Example**: Reformulating §B at Build then defending the choice at Validate as a Walked deviation, when Analysis could have pre-locked it as a Plan decision.

- **Anti-Pattern 3: Pre-locking Strip Without Mental Sim Per Section**
  - **Why Wrong**: Locks branch 1 (row-strip) for every section in scope without checking whether the section's guidance survives the strip. Misses cases that should be branch 3.
  - **Example**: "Strip all multi-env vocab across 13 files" as a single locked treatment, without per-section Mental Sim, leaves guidance-vacuum cases undetected until Build write.

## Relationships

- **Requires**: PAT-085 clarity-over-compression (the technique branch 3 invokes)
- **Enhances**: PAT-098 grep-before-rename (Analysis sampling becomes the discovery surface for branch-3 candidates), PAT-049 foundation-first-repair (per-section Mental Sim aligns with cascade-companion order-of-operations)
- **Conflicts**: None
- **Alternatives**: Reactive PAT-085 at Build (works but loses the Analysis-lock benefit)

## Consequences

### Benefits

- **Compressed decision distance**: Reformulation moves from Build-discovery → §POST-TYPE Walk → Validate re-affirm into Analysis-lock → Build-execute. Three downstream phases relieved of a discovery they don't need to make.
- **Cleaner Build phase**: Build becomes execution of locked decisions, not discovery of architectural calls. §POST-TYPE deviation analysis is smaller and more targeted.
- **Validate independence preserved**: Validate still adversarially re-checks the reformulation, but as a locked-decision review rather than a fresh architectural call.
- **Pattern fit anchored at Analysis**: PAT-085 firing sites are inventoried during Analysis Topic 1, not discovered ad-hoc at Build.

### Tradeoffs

- **Analysis cost**: Per-section Mental Sim pass adds time at Analysis. Offset: amortized across all sections in scope; usually fast.
- **Pre-lock rigidity**: A pre-locked branch 3 reformulation may need revision at Build if surrounding context shifts. Mitigation: pre-lock the *site and PAT-085 application*, not the exact replacement text — leave wording for Build with the architectural call already made.

### Risks

- **Over-application**: Treating every section as a candidate for branch 3 inflates Analysis. Mitigation: Mental Sim is the gate — only sections where guidance vacuum is real qualify.

## Examples

### Before: ISS-193 Analysis Topic 1 (LOCKED two branches)

> Topic 1 vocab-strip treatment LOCKED — Option A section-removal when vacuous (target-anchored). Remove entire `###` subsections whose purpose dissolves under single-env, not just row-strip.

→ §B rename in nexus-maintain surfaces at Build Mental Sim, requires Implementation-Log Deviation + §POST-TYPE Walk + Validate re-affirm.

### After: Equivalent Analysis with branch 3 pre-locked

> Topic 1 vocab-strip treatment LOCKED — three branches: (1) row-strip; (2) section-removal when vacuous of content; (3) PAT-085 reformulation when pure strip leaves a section vacuous of guidance. Per-section Mental Sim at Investigate identifies branch assignments per `###` heading in scope.

> Pre-locked branch 3 sites: nexus-maintain §B (mode-selection guidance survives the strategic shift; reformulate to tier-based statement per PAT-085).

→ Build executes the locked decision; §POST-TYPE Walk is shorter; Validate confirms a planned reformulation, not a discovered one.
