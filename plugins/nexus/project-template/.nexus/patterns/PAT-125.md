# PAT-125: Negative Space Verification
*Version: 1.0.0 | Date: 2026-06-12 | Sprint: 102*

## Metadata
- **Type**: principle
- **Status**: active
- **Created**: 2026-06-12

## Problem

Schema-enforced multi-agent collection produces an illusion of completeness. When every agent fills in every field, the output appears verified — but forced classification guarantees response *coverage*, not answer *correctness*. On interpretation-sensitive criteria, agents may systematically diverge from the intended reading, and the misclassification hides in the "pass/clean/absent" cells that spot-checks routinely skip in favor of the volunteered positive findings (the defects, hits, fails). A findings-only spot-check protocol is structurally blind to this failure mode.

## Context
- **Use When**:
  - Running schema-enforced fan-out collection where any criterion carries semantic interpretation ambiguity (audit passes, LLM-judge rubrics, batch classifiers, quality-gate digests)
  - Designing spot-check protocols for structured-output agents — encode a negative-space quota (e.g., ≥1 clean/pass/absent cell per digest per interpretation-sensitive criterion) explicitly alongside findings sampling
  - Before publishing quantitative claims derived from schema-forced boolean or enum fields (pass rates, coverage counts, per-criterion prevalence)
  - When a criterion's precise rule was still being derived at fan-out dispatch time — treat pre-derivation classifications of that criterion as provisional; revalidate negative-space cells after the rule is locked
  - CAUTION: skip for deterministic criteria with no semantic ambiguity (file existence checks, exact string matches, numeric comparisons against a fixed threshold)
- **Not When**: Single-source or manually-applied classifications where the operator reads the source and classifies directly (no silent multi-agent divergence risk)
- **Prerequisites**: A schema-enforced collection fan-out (Workflow agent() with schema, LLM judge, or batch classification run) where some agents may interpret a criterion differently

## Solution

Before the fan-out, **lock interpretation-sensitive criteria with a worked example** at dispatch time — not post-derivation. A criterion whose precise rule the wave is still discovering should be tagged as provisional; its negative-space cells must be revalidated once the rule is finalized.

At validation time, **deliberately sample a quota of negative-space cells** (pass/clean/absent/zero classifications) in addition to the volunteered positive findings. A practical minimum: ≥1 clean/pass cell per digest agent for each interpretation-sensitive criterion. The negative-space sample should probe cells where the agent answered "nothing to flag" — these are exactly where systematic misclassification hides.

Encode the negative-space sampling quota **explicitly in the spot-check protocol** (not left to judgment at execution time). Findings-only sampling is the default instinct and must be overridden by a stated rule.

### Implementation
1. At research/audit design time: identify which criteria carry interpretation ambiguity.
2. For each interpretation-sensitive criterion: write a worked example (one clear "pass" case, one clear "fail" case) into the dispatch prompt before the fan-out. If the example can't be written yet, mark the criterion provisional.
3. At spot-check time: for each agent digest, sample at least one negative-space cell (clean/pass/absent) per interpretation-sensitive criterion in addition to the positive findings. Read the source artifact directly and re-classify.
4. Before publishing any quantitative claim from a schema-forced field: verify the cell-level classification in a random sample of the claimed-clean entries, not just the count.

### Quick Reference
| Step | Action | Guard |
|------|--------|-------|
| Design | Identify interpretation-sensitive criteria | Write worked examples before dispatch |
| Dispatch | Include examples in agent prompts | If rule still emerging, mark provisional |
| Spot-check | Sample ≥1 negative-space cell per criterion per digest | Encode as explicit protocol rule, not judgment |

## Rationale
- **Theoretical Basis**: Schema-forcing closes the coverage gap (every agent answers) but not the validity gap (every answer is correct). These are orthogonal properties. Verification effort that follows only the positive signal leaves a systematic blind spot in the unverified negative space — if agents misclassify "clean" items, those errors survive any findings-only check.
- **Empirical Evidence**: ISS-207 (Sprint 102) — two of eight digest agents marked imperative descriptions `third_person=true` under ambiguous v2.1 criterion wording, inflating the reported pass count from 0 to 12 (44/44 true fail vs. reported 32/44 fail). The 15 spot-checks all sampled volunteered positive findings; none sampled the `third_person=true` cells. The miscount survived to the consolidated report, the playbook, and a downstream issue scope — caught only at independent Evaluation re-read of source. Now documented as playbook Lesson 13.
- **Design Decisions**: Sampling the negative space is a targeted supplement, not a full re-verification. The goal is to detect systematic divergence early at low cost; a quota of one clean cell per criterion per agent is sufficient to surface a group-level divergence pattern.

## Anti-Patterns

- **Anti-Pattern 1: Findings-Only Spot-Check**
  - **Why Wrong**: If agents misclassify "clean" items, those errors live exclusively in the cells spot-checks by definition skip. Sampling only volunteered defects certifies nothing about classification accuracy.
  - **Example**: 15 spot-checks across 7 digest groups all selected the agents' explicit findings; zero checks touched `third_person=true` cells; the inflation went undetected.

- **Anti-Pattern 2: Schema-Forced = Verified**
  - **Why Wrong**: "The agent filled in the field" is a coverage statement. It says nothing about whether the value is correct. Treating structured output as validated output collapses a distinction that matters precisely when criteria are hard to judge.
  - **Example**: "All digests returned `third_person` booleans — zero conformance errors" was true. The values were still wrong for two groups.

- **Anti-Pattern 3: Post-Fan-Out Criterion Locking**
  - **Why Wrong**: If the classification rule is finalized *after* agents have already run, the pre-derivation classifications may be subtly inconsistent with the locked rule. Retroactively applying the new rule to reported counts (without resampling) produces numbers that look precise but are mixed-generation composites.
  - **Example**: The "imperative fails" rule was a v3 *output* of the ISS-207 wave. Agents dispatched under v2.1 could not have applied it consistently.

## Relationships
- **Requires**: A schema-enforced collection mechanism (structured-output agents, LLM judges, batch classifiers)
- **Enhances**: PAT-095 (isolated-context-advantage — adds negative-space sampling to its result-contract design), PAT-112 (explicit-discipline — the negative-space quota IS an explicit pre-baked discipline)
- **Conflicts**: []
- **Alternatives**: Full re-verification of all classifications (overkill for large fan-outs; this pattern targets the minimum viable sample); manual classification by a single operator (eliminates multi-agent divergence risk entirely)

## Consequences
- **Benefits**: Catches systematic multi-agent classification drift at low spot-check cost; separates the coverage proof from the validity proof; surfaces interpretation ambiguity that calibration alone cannot detect
- **Tradeoffs**: Slightly larger spot-check surface (negative-space cells + positive findings vs. positive findings alone); requires upfront criterion clarity that may not exist before the fan-out
- **Risks**: A small negative-space sample may miss divergence in one subgroup while other subgroups are clean (ISS-207 had 2 of 8 groups diverge); larger samples or per-group coverage improve confidence at higher cost

## Examples

### Before/After Comparison
**Without Pattern**: Spot-check protocol samples 15 findings across 7 digest agents (≥2 per digest). All 15 verify against source. Report claims 44/44 fail on `third_person` criterion based on schema-forced boolean. Two agents actually classified 12 files as `third_person=true` under an ambiguous rule — but those cells were never sampled.

**With Pattern**: Spot-check protocol adds: for each digest, sample ≥1 `third_person=true` cell (the negative space — agent says "passes" on this criterion). At validation, re-read that source file and apply the criterion. Two groups fail this check: the files they marked `true` are imperative-form, not third-person. Miscount surfaced before the consolidated report.

## Validation
- **Success Indicator**: Spot-check protocol documentation explicitly names a negative-space quota; the quota fires during execution (a "clean" cell is re-read and confirmed against the criterion definition)
- **Edge Cases**: When all agents consistently agree on a criterion (no divergence visible in positive findings either), the negative-space sample may be confirmatory rather than corrective — still valuable as evidence of consistency

## Notes and Observations
The distinction between coverage proof and validity proof generalizes beyond LLM-agent collection: any pipeline that forces a response (schema validation, required form fields, mandatory rubric rows) provides coverage guarantees, not content guarantees. The negative-space sampling discipline applies wherever a forced-answer format creates an appearance of complete verification.
