# PAT-143: Diff Parallel Reports Against Each Other
*Version: 1.0.0 | Date: 2026-08-25 | Sprint: 110*

## Metadata
- **Type**: practice
- **Status**: active
- **Created**: 2026-08-25

## Problem

When work is fanned out to N isolated workers, reviewers, or auditors over a shared source of truth, every quality check runs along the same axis: each report is graded against the source, and against its own target. Nothing compares the reports **to each other**.

So two workers can return opposite verdicts on the same shared fact with both reports internally clean and both authors non-negligent — each consulted a different authoritative file, each drew a defensible conclusion, and per-target conformance is structurally blind to the disagreement. Run sequentially, that same fact would have been decided once, silently, and one of the two answers would simply have been wrong with nothing to mark it.

The reviewer-level form is worse: when two reviewers disagree, the instinct is to break the tie — by majority, by stated confidence, or by seniority. Every tie-break picks one of the two readings on the table, and the actual answer is often a third state neither reviewer considered.

## Context

- **Use When**:
  - Dispatching a batch or sub-agent fan-out where multiple workers touch the same triggers, thresholds, file inventory, or vocabulary
  - Reconciling findings from two or more independent reviewers over one artifact
  - Designing the return protocol for a parallel audit — deciding what workers must report, not just what they must do
  - A parallel run finished and every individual report passed its own conformance check
- **Not When**:
  - Units are genuinely disjoint with no shared facts between them — there is nothing to diff
  - Only one worker or reviewer ran, sequentially; the signal this pattern reads does not exist
  - The shared fact is machine-derived identically for every worker (a checksum, a generated manifest) rather than judged
- **Prerequisites**: Workers can be instructed to report verdicts on shared facts, not only per-target diffs.

## Solution

Make the reports themselves a comparison surface.

**Before dispatch**, name the shared facts — the triggers, thresholds, file existences, vocabulary decisions and conventions that more than one worker will have to form a view on — and require each worker to report an explicit verdict on every shared fact it touched, with the source it consulted. A per-target diff is not enough; a verdict without its source cannot be reconciled.

**After return, before accepting anything**, extract every verdict on a shared fact and diff the reports against each other. Treat any disagreement as blocking for that fact.

**On disagreement, resolve to a primary source.** Never to a majority, a confidence level, or the more senior reviewer. Disagreement is evidence that the **question** is underspecified, not merely that one party erred — each side found real evidence for a different reading, so any tie-break that picks a side inherits the unexamined option neither side raised. Go to the authoritative artifact, and budget for that resolution step explicitly, because it is invisible when reviewers happen to agree.

### Implementation

1. Enumerate the shared facts before dispatch; put them in the brief by name.
2. Require the return format to carry: fact, verdict, source consulted.
3. On return, build the verdict matrix — facts down, workers across.
4. Every row with more than one distinct verdict is blocked pending primary-source resolution.
5. Resolve each blocked row against the authoritative artifact, not against the reports. Record the resolution and which reports were wrong.
6. Only then accept the per-target work.

## Rationale

- **Theoretical Basis**: Independent workers have independent failure modes, so agreement is weak evidence and *disagreement is strong evidence* — but only if someone looks. Parallelism is normally justified on throughput; the cross-report diff converts it into a correctness instrument, because the same fact getting two independent judgments is a redundancy that sequential execution cannot produce at any price. And because both judgments can be wrong together, the tie-break must leave the reports entirely: the disagreement points at an under-specified question, and the answer lives in the source, not in the pair of answers.
- **Empirical Evidence**: ISS-089 (Sprint 110) produced the failure at two levels in two conversations. **Worker level**: two batch workers reached opposite verdicts on the phrase `"switch to themed/mixed"` — one kept it as a live trigger, one deleted it as dead. Neither was negligent; each had checked a different authoritative file, and each report was internally clean and passed its own conformance check. Resolved against the routing map, where the phrase appears in neither the map nor any skill. **Reviewer level**: two reviewers reached opposite verdicts on whether a set of identifiers was live or fabricated — one cited a surviving mention, one cited a zero-hit grep. **Both were wrong.** The identifiers were *retired*, a third state neither had considered, recorded in a verification log neither had read. Separately, an independent review pass found eleven cross-guide contradictions after a self-authored set-level sweep had reported that same surface clean, because the self-sweep was keyed on a hand-written regex and could only find contradictions in the categories its author thought to enumerate.
- **Design Decisions**: The verdict-reporting requirement sits in the *brief*, not in the review step, because a report that only carries per-target diffs cannot be reconciled after the fact — the workers are gone. Making the return format carry the source alongside the verdict is what makes primary-source resolution cheap instead of a re-investigation.

## Anti-Patterns

- **Anti-Pattern 1**: Grading each report only against the source and against its own target.
  - **Why Wrong**: Both are same-axis checks. Cross-worker disagreement is orthogonal to both and cannot be seen from either.
  - **Example**: Seven per-target conformance passes, all clean, over a corpus containing one live contradiction between two of them.
- **Anti-Pattern 2**: Breaking a reviewer tie by confidence, majority, or seniority.
  - **Why Wrong**: It selects from the readings on the table. When both are wrong, the tie-break guarantees the wrong answer and closes the question.
  - **Example**: Choosing "live" over "fabricated" for identifiers that were actually retired.
- **Anti-Pattern 3**: Accepting a worker's existence claims, counts, and verdicts at face value because the report is well-formed.
  - **Why Wrong**: Report quality and claim accuracy are independent. A high-quality report can carry a confidently wrong existence claim.
  - **Example**: A pilot reporting a folder "confirmed absent" that exists and is empty.
- **Anti-Pattern 4**: Justifying parallelism on throughput alone.
  - **Why Wrong**: It leaves the correctness dividend unclaimed and makes the cross-report diff look like optional overhead rather than the reason the fan-out was worth it.

## Consequences
- **Benefits**: Turns parallel execution into a correctness instrument rather than only a throughput one · catches the class per-target conformance cannot see · replaces tie-breaking with source resolution, which also surfaces unconsidered third states.
- **Tradeoffs**: The brief gets longer and the return format more rigid · the reconciliation step must be budgeted even in the common case where reports agree and it finds nothing.
- **Risks**: Enumerating shared facts before dispatch is itself an enumeration problem — facts nobody listed are not diffed. Treat any surprise disagreement on an unlisted fact as evidence the list was short, not as an anomaly.

## Examples

### Before/After Comparison

**Without Pattern**: Ten workers process ten targets. Each report is checked against its target and against the source specification; all ten pass. Two of them disagree about whether one shared trigger phrase is live, and the disagreement is never surfaced — one target keeps a dead trigger, another deletes a live one, and both edits ship.

**With Pattern**: The brief names the trigger phrase as a shared fact and requires a verdict plus a source. On return, the verdict matrix shows one row with two distinct answers. The row is blocked, resolved against the routing map, and both targets are corrected before anything is accepted.

### Application Example

Two reviewers were asked whether a set of identifiers was live. One found a surviving mention and said live; one ran a zero-hit grep and said fabricated. Rather than picking the more confident reviewer, the disagreement was treated as a pointer to an unexamined source — a verification log neither had read — which recorded the identifiers as **retired**. The correct answer was in neither report.

## Validation
- **Success Indicator**: The run's record contains a verdict matrix (facts × workers) with every multi-verdict row marked resolved and citing the primary source consulted.
- **Edge Cases**: When all workers agree on a shared fact, the diff finds nothing and still cost time — that is the expected common case, not a sign the step is unnecessary. Its value is priced like insurance.

## Notes and Observations

The two levels were found one conversation apart and neither instance would have been caught by the other's remedy — the worker-level case needed a verdict field in the return format, the reviewer-level case needed a rule about how to resolve. They are one pattern because the underlying fact is the same: **when independent judgments exist, comparing them is a free correctness check that nobody performs by default.**

Worth carrying separately: a self-authored contradiction sweep is bounded by its author's imagination of what might disagree. That is why an independent pass found eleven contradictions on a surface the self-sweep had reported clean — and it is the reason this pattern's value survives even when the fan-out was justified on cost alone.
